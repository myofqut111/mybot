# 无线链路调优

> 症状：路由器（FAST 这类入门机）在跑导航/加视觉节点时会**整体死掉**——
> 所有设备断开、连路由器后台都进不去。拔掉设备或重启路由器就好。

## 结论先说

不是你的程序有 bug，也不是带宽不够（导航全套才 ~100 KB/s、地图才 70 KB）。
是 **WiFi 空口被"小帧"压死的**：

1. **DDS 多播发现**——Fast-DDS 默认靠多播找节点。多播帧在 WiFi 上按
   1 Mbps 最低速率广播、无确认、每个客户端都要处理，对便宜路由器的
   转发队列是灾难。
2. **视觉节点的原始图像**——320×240×3 × 5 fps ≈ **9 Mbps**，是导航的 60 倍。

## 两个脚本

| 文件 | 干什么 |
|---|---|
| `setup_dds_unicast.sh` | 把 DDS 发现从多播改成「只跟指定机器单播」。只写 `~/.dds_unicast/`，**不改系统配置**。 |
| `net_diag.sh` | 一眼看清：谁在吃带宽、多播帧多不多、接口有没有错误计数。 |

## 怎么用

在**每一台**要参与通信的机器上各跑一次，参数填**对方的 IP**（自己的可以不填）：

```bash
# 在 VM（192.168.1.103）上：
bash tools/net/setup_dds_unicast.sh 192.168.1.50      # 填 Jetson 的 IP

# 在 Jetson（192.168.1.50）上：
bash tools/net/setup_dds_unicast.sh 192.168.1.103     # 填 VM 的 IP
```

然后**在跑 demo 的那个终端里**启用（只影响这个终端）：

```bash
source ~/.dds_unicast/env_dds.sh
ros2 launch ...
```

## 怎么验证

```bash
bash tools/net/net_diag.sh          # 自动找默认路由那张网卡
```

- 「多播帧密度」应该从上百掉到接近 0（`tcpdump` 需要 sudo）；
- 各话题带宽正常；
- `ros2 node list` 能看到对方的节点。

## 怎么撤销

```bash
unset FASTRTPS_DEFAULT_PROFILES_FILE
```

或直接关掉那个终端。系统里什么都没改。

## 注意事项

- **两边都要配**，而且都要把对方 IP 填进去。只配一边 → 谁也发现不了谁
  （现象：`ros2 node list` 只有自己）。
- 板子的 micro-ROS **不受影响**：XRCE-DDS 用自己的 UDP 8888 会话，
  不走 DDS 发现。
- 新加机器（比如换一台笔记本）时，要把它的 IP 加进各机器的 peers 列表，
  否则它看不见别人——这是关多播的代价。
- 如果只想先少改点，**先做「视觉节点 `publish_rate:=0`」这一条**，
  它单独就能把 9 Mbps 降到 0。
