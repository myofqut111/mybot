# 巡检 × 视觉 联调指令手册

版本：巡检执行器 **v0.3.2** / 视觉节点（capture 轮询 + v5 权重）
更新：2026-10-26

> 这份手册只写"要敲什么、看到什么算对"。设计原理见 `巡检v2代码详解.md`，
> 参数含义见 `README.md`。

## 0. 这一版相对上一版手册改了什么

| 变化 | 说明 |
|---|---|
| 巡检 0.2.5 → 0.3.2 | 主动走近复核、结果看板、电量显示、Ctrl+C 真取消、一条 launch 拉全链路 |
| 视觉取图 | MJPEG 长连接 → **`/capture` 单张轮询**（ESP32 httpd 扛不住长连接） |
| 视觉模型 | v4 → **v5**（加了 157 张负样本重训） |
| 视觉阈值 | conf 0.25 → **0.15**（v5 在 0.15 的召回追平 v4，误报只有 1/13） |
| 任务编号 | 执行器发出的 `execution_id` 一律带 `-L{轮}-A{第几次尝试}`，旧格式 `-1` 说明那个进程是老版本 |

## 3. 启动

### A. 一条命令（推荐）

在**虚拟机上**（巡检三件套 + 看板）：

```bash
ros2 launch fishbot_patrol_v2 patrol_v2.launch.py
```

在**机器人上**（视觉）：

```bash
ros2 launch fishbot_vision vision.launch.py
```

如果视觉和巡检在同一台机器上，也可以一把拉起：

```bash
ros2 launch fishbot_patrol_v2 patrol_v2.launch.py vision:=true
```

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `failure_policy` | `skip` | `stop` 停下 / `skip` 跳过 / `retry` 重试 |
| `resume` | `true` | 从上次进度继续（关掉就每次从头） |
| `report_dir` | `~/patrol_reports` | 报告目录 |
| `task_manager` | `true` | 是否同时起任务管理器 |
| `route_manager` | `true` | 是否同时起路线管理器 |
| `task_timeout_s` | `120.0` | 单点位任务超时 |
| `vision` | `false` | 是否同时起视觉（需本机装了 fishbot_vision） |
| `nav` | `false` | 是否同时起导航（通常跑在虚拟机上） |

### B. 分终端（排查用）

```bash
# 终端 1：路线管理
ros2 run fishbot_patrol_route_manager route_manager
# 终端 2：任务管理
ros2 run fishbot_patrol_task_manager patrol_task_manager
# 终端 3：执行器
ros2 run fishbot_patrol_v2 patrol_executor_v2
# 终端 4：看板（可选）
ros2 run fishbot_patrol_v2 patrol_viewer
```

### C. 一键跑一轮

```bash
# patrol.sh 随包装到 share/fishbot_patrol_v2/tools/ 下，不是 ros2 run 子命令
SH=$(ros2 pkg prefix fishbot_patrol_v2)/share/fishbot_patrol_v2/tools/patrol.sh
bash "$SH"                 # 默认路线 main，跑 1 轮
bash "$SH" main 0 1        # 路线 main，once，1 轮
bash "$SH" main 1 3        # 路线 main，repeat，3 轮
```

它会在后台拉起 launch、等 action server 上线、前台发目标并打印反馈，跑完自动收尾。
（第一次用可以先 `bash "$SH" --help` 看用法。）

### 停止

| 想干什么 | 命令 |
|---|---|
| 取消当前巡检（车停下） | 在 launch 终端 `Ctrl+C`（v0.2.2 起会先取消 Nav2 目标再退出）；用 `patrol.sh` 启动的话，直接在它那个终端 `Ctrl+C` |
| 暂停 / 恢复 | `ros2 service call /patrol/pause fishbot_patrol_interfaces/srv/PausePatrol "{}"`<br>`ros2 service call /patrol/resume fishbot_patrol_interfaces/srv/ResumePatrol "{}"` |
| 只让当前点位作废、继续跑 | 发布抢占：`ros2 topic pub --once /patrol/preempt std_msgs/msg/String "{data: ''}"`（空串=只记录不跳转） |

> **注意**：Humble 的 `ros2 action` 没有 `cancel` 子命令，在 `send_goal` 那个终端按
> `Ctrl+C` 也**不会**取消服务端目标——车会继续把这一轮跑完。要真停下就动 launch 终端。

## 4. 存路线

前提：**定位已经起来并且收敛**（否则采到的点位是飘的）。

```bash
# 开一个终端，把车开到目标位置，然后：
ros2 topic echo /amcl_pose --once         # 确认有定位

ros2 service call /patrol_route/record_point \
  fishbot_patrol_interfaces/srv/RecordPoint \
  "{route_name: 'main', point_id: 'p1', task_id: 'inspect'}"
```

| 字段 | 说明 |
|---|---|
| `route_name` | 路线名，可多路线并存 |
| `point_id` | 点位名，**同路线内不能重复**；留空会自动 `point_001`、`point_002`… |
| `task_id` | 到点要干什么，`inspect`（默认）/ `detect` / `vision` / `yolo` 都会触发视觉 |

同一条路线里所有点必须**同一个坐标系**（`frame_id` 不一致会直接报错）。

存完查看：

```bash
ros2 service call /patrol_route/get fishbot_patrol_interfaces/srv/GetRoute "{route_name: 'main'}"
cat ~/.ros/fishbot_patrol_routes.json          # 也可以直接看文件
```

其它操作：

```bash
ros2 service call /patrol_route/set_active fishbot_patrol_interfaces/srv/SetActiveRoute "{route_name: 'main'}"
ros2 service call /patrol_route/clear fishbot_patrol_interfaces/srv/ClearRoute "{route_name: 'main'}"
```

**加分项——给点位加期望值**：在 json 里给每个点加 `"expect": "present"` 或 `"absent"`，
这样每跑一轮就能自动算出 TP/FP/FN/TN，不用人工核对。空会议室写 `absent`，
灭火器旁边写 `present`。

## 5. 跑一轮 + 看结果

```bash
# 发目标
ros2 action send_goal /execute_patrol \
  fishbot_patrol_interfaces/action/ExecutePatrol \
  "{route_name: 'main', mode: 0, repeat_count: 1}" --feedback
```

`mode`：`0`=once、`1`=repeat、`2`=random。

### 实时看板

```bash
ros2 run fishbot_patrol_v2 patrol_viewer
```

表头每帧刷新，含：当前点位、已用时间、检测到的目标与置信度、本轮成功/失败点数、
电量（低于阈值会标红）。退出后两张表会以 CSV 落盘到 `--out-dir`（默认 `~/patrol_viewer`）。

```bash
# 换输出目录、调电量阈值、关掉实时刷新只落盘
ros2 run fishbot_patrol_v2 patrol_viewer --ros-args \
  -p out_dir:=$HOME/patrol_reports -p battery_warn_v:=11.8 -p battery_crit_v:=11.5 \
  -p live:=false
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `out_dir` | `~/patrol_viewer` | CSV 落盘目录 |
| `live` | `true` | `false` 只在结束时写表 |
| `show_external` | `false` | 是否显示视觉直发的外部结果 |
| `battery_topic` | `/battery/voltage` | 电池电压话题 |
| `battery_warn_v` / `battery_crit_v` | `11.8` / `11.5` | 黄色 / 红色阈值 |

### 报告

```bash
ls -lt ~/patrol_reports | head            # 每轮三件套：.jsonl / .summary.json / .csv
```

汇总多轮：

```bash
python3 ~/fishbot_full_ws/src/fishbot_patrol_v2/tools/summarize_runs.py --dir ~/patrol_reports
# 只看最近 3 次：--last 3 ；另存 CSV：--csv ~/summary.csv
```

输出每次运行一行（点数、成功、跳过、失败、总耗时、平均单点耗时、检出率），
最后给一段总体统计——这是写报告要用的数字。

## 6. 视觉联调要点

### 6.1 确认跑的是对的那个模型

启动日志第一行必须是：

```
Loading YOLO model: .../share/fishbot_vision/fire_extinguisher.pt ...
yolo_detector started, ..., conf=0.15, ...
```

如果出现 `yolo26n.pt`、或者 `bottle` / `person` 这类 COCO 类名，说明模型错了
（launch 里的默认值盖掉了 yaml，或者装的是老副本）。

### 6.2 相机不通的三步排查

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.100/capture   # 200 正常
arp -n | grep 192.168.1.100                                            # 看 MAC 在不在
curl -s http://192.168.1.100/status | head -c 200                      # 看参数
```

| 现象 | 结论 |
|---|---|
| ping 不通、ARP 里也没有 | 没通电 / 没连这个网 |
| ping 不通、ARP 里有 MAC 但状态 STALE | 掉线，等 10 s 或断电重启 |
| ping 通、80/81 全超时 | **httpd 卡死，必须断电重启**（这是这颗 ESP32 的固件毛病） |
| 能取图但很慢（>1 s/张） | 热点/信号问题，换个位置或接回路由器 |

### 6.3 分辨率必须是 640×480

```bash
curl -s http://192.168.1.100/status | grep -i framesize
curl -s -o /tmp/c.jpg http://192.168.1.100/capture && python3 -c "
import struct;d=open('/tmp/c.jpg','rb').read();i=2
while i<len(d)-9:
    if d[i]!=0xFF:i+=1;continue
    m=d[i+1]
    if m in(0xC0,0xC1,0xC2):
        h,w=struct.unpack('>HH',d[i+5:i+9]);print(w,'x',h);break
    ln=struct.unpack('>H',d[i+2:i+4])[0];i+=2+ln"
```

ESP32 断电或客户端断开后会**自己退回 320×240**，所以每次联调前都值得看一眼。

### 6.4 手动拍照（攒负样本/补数据）

```bash
python3 ~/fishbot_full_ws/src/fishbot_vision/scripts/photo.py --count 20 --interval 0.5
```

打到 `~/shots/`，文件名带时间戳，不会覆盖。

## 7. 走近复核（v0.3.2 新功能）

置信度落在灰区时，车往前挪 0.4 m 再看一眼，最多 2 次。开关和阈值都在 `patrol_v2.yaml`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `recheck_forward_m` | `0.4` | 每次前进距离，设 `0.0` 就关掉 |
| `recheck_max_rounds` | `2` | 最多走近几次 |
| `recheck_conf_low` | `0.25` | 低于它算"没看到"（会继续走近确认） |
| `recheck_conf_high` | `0.60` | 高于它直接确认，不再走近 |
| `recheck_on_miss` | `true` | 完全没检出也走近确认（压漏检） |

**怎么知道它触发了**：报告里该点位会出现一条 `recheck` 事件，`message` 尾部带
`[recheck +0.4m, top=0.52]`；看板的备注列也会显示。

**什么时候别开**：走廊很窄、点位贴着墙（前进 0.4 m 会撞）。先把
`recheck_forward_m` 降到 `0.2`，或对那条路线单独关掉。

## 8. 电量

固件通过 micro-ROS 发 `/battery/voltage`（`std_msgs/Float32`），1 Hz。

```bash
ros2 topic hz /battery/voltage
ros2 topic echo /battery/voltage --once
```

看板电量列的三档：正常（>11.8 V）、偏低（11.5~11.8 V，黄）、告警（<11.5 V，红）。

标定方法：万用表量电池端电压，同时读 `/battery/voltage`，按比例改固件里的
`BAT_DIVIDER_RATIO`。**默认 5.0 只对 5:1 分压电阻有效**，没量过就别信绝对值。

## 9. 排障表

| 症状 | 根因 | 处理 |
|---|---|---|
| `'bool' object is not callable` | 旧版把 `goal_handle.is_cancel_requested`（属性）当回调传 | 装 ≥0.2.5；`grep -c "cancel_check=lambda" <node.py>` 应为 1 |
| `ignored unmatched external result ...-1` | 有老版本执行器在发 `-1` 格式的 id | `ros2 topic info /patrol/task/request -v` 看发布者；杀掉旧进程 |
| `requesting incompatible QoS ... DURABILITY` | 视觉发外部结果是 VOLATILE，任务管理器订阅要 TRANSIENT_LOCAL | 视觉侧订阅改 VOLATILE（v0.2.9 起已改） |
| 点位全部 `SUCCEEDED` 但没检测结果 | `task_id` 不在白名单 | 用 `inspect`/`detect`/`vision`/`yolo` |
| `Stale frame (2.0s old...)` | 相机断流 | 见 6.2；capture 模式下不该出现，出现说明相机挂了 |
| 首次连接必断、重连后正常 | ESP32 长连接缺陷 | 已改成 `/capture` 轮询，`capture_mode: true` |
| `colcon build` 只用 1.4 秒、版本没变 | 时钟回 1970，make 认为源码没更新 | `rm -rf build/x install/x` 再编；先把时钟修好 |
| `Duplicate package names` | `src/` 里有 `xxx.bak.时间` 备份目录 | 把备份挪出 `src/`，或放一个 `COLCON_IGNORE` |
| `ModuleNotFoundError: fishbot_patrol_v2` | 没 `source install/setup.bash`，或包没编过 | 重新 source；`ros2 pkg xml` 验证 |
| 到点位不停稳就判成功 | 容差放宽到 0.30 m / 0.60 rad | 改 `final_position_tolerance_m: 0.10` |
| 电池读数乱跳 | 满载压降 | 看板取中值；判定只在停稳时做 |
| 相机 IP 变了 | 热点 DHCP | 设静态 IP，或改 `stream_url` |

## 12. 升级巡检包

把新 zip 传到虚拟机后，一条命令完成"备份旧包 → 解包覆盖 → 清 build/install → 重编 → 验证"：

```bash
bash ~/fishbot_patrol_v2/tools/upgrade_patrol.sh ~/fishbot_patrol_v2.zip
```

几点注意：

- **备份目录不能留在 `src/` 里**，否则 `colcon` 会把 `xxx.bak.时间` 当成第二个同名包，
  直接报 `Duplicate package names`。挪到 `~/patrol_backups/`，或者在备份里放一个空的
  `COLCON_IGNORE`。
- `colcon build` 只用 1~2 秒就"成功"，通常不是好事：多半是**系统时钟回退**导致 make
  认为源码没变。先 `date` 看一眼，不对劲就 `rm -rf build/x install/x` 重编。
- 编完一定要**重启 launch**，老进程里还是老代码。

## 附：一次完整的联调流程（照着敲）

```bash
# 0) 虚拟机上
source /opt/ros/humble/setup.bash && source ~/fishbot_full_ws/install/setup.bash

# 1) 确认相机
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.100/capture   # 要 200

# 2) 起视觉（机器人上）
ros2 launch fishbot_vision vision.launch.py
#    看到 "YOLO model loaded" + "camera capture polling 5.0Hz (640x480)"

# 3) 起导航（虚拟机上，若还没起）
ros2 launch fishbot_navigation navigation.launch.py

# 4) 起巡检
ros2 launch fishbot_patrol_v2 patrol_v2.launch.py

# 5) 确认定位收敛
ros2 topic echo /amcl_pose --once

# 6) 存 3 个点
```
