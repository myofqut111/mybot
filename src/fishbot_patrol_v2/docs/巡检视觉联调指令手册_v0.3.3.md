版本：巡检执行器 **v0.3.3**（接口包 **0.2.0**）/ 视觉节点（capture 轮询 + v5 权重）
更新：2026-10-29

> 这份手册只写"要敲什么、看到什么算对"。设计原理见 `巡检v2代码详解.md`，

## 0. 这一版相对 v0.3.2 改了什么

| 变化 | 说明 |
|---|---|
| 电量决策（新） | 订阅 `/battery/voltage`，中值滤波 + 迟滞；低电时**跑完当前点再中止**，不停在走廊中间 |
| 期望值判定（新） | 点位可带 `expect: present/absent`，自动产出 tp/fp/fn/tn 与召回/准确/误报率 |
| 存路线接口（变） | `RecordPoint.srv` 多了 `string expect` 字段，存点当时就能写期望值 |
| **接口包升 0.2.0** | 消息定义变了，`fishbot_patrol_interfaces` 与 `fishbot_patrol_v2` **必须一起重编**，只换一个会出现"发出去没人收" |
| 报告字段（扩） | summary 多了 `verdicts`、`graded_points`、`recall`、`precision`、`false_alarm_rate`、`battery_v`、`battery_level` |

v0.3.2 及更早的内容（走近复核、看板、Ctrl+C 真取消、一条 launch 拉全链路）保持不变。

## 3. 启动

### A. 一条命令（推荐）

在**虚拟机上**（巡检三件套 + 看板）：

```bash
ros2 launch fishbot_patrol_v2 patrol_v2.launch.py
```

在**机器人上**（视觉）：

```bash
ros2 launch fishbot_vision vision.launch.py
```

如果视觉和巡检在同一台机器上，也可以一把拉起：

```bash
ros2 launch fishbot_patrol_v2 patrol_v2.launch.py vision:=true
```

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `failure_policy` | `skip` | `stop` 停下 / `skip` 跳过 / `retry` 重试 |
| `resume` | `true` | 从上次进度继续（关掉就每次从头） |
| `report_dir` | `~/patrol_reports` | 报告目录 |
| `task_manager` | `true` | 是否同时起任务管理器 |
| `route_manager` | `true` | 是否同时起路线管理器 |
| `task_timeout_s` | `120.0` | 单点位任务超时 |
| `vision` | `false` | 是否同时起视觉（需本机装了 fishbot_vision） |
| `nav` | `false` | 是否同时起导航（通常跑在虚拟机上） |

### B. 分终端（排查用）

```bash
# 终端 1：路线管理
ros2 run fishbot_patrol_route_manager route_manager
# 终端 2：任务管理
ros2 run fishbot_patrol_task_manager patrol_task_manager
# 终端 3：执行器
ros2 run fishbot_patrol_v2 patrol_executor_v2
# 终端 4：看板（可选）
ros2 run fishbot_patrol_v2 patrol_viewer
```

### C. 一键跑一轮

```bash
# patrol.sh 随包装到 share/fishbot_patrol_v2/tools/ 下，不是 ros2 run 子命令
SH=$(ros2 pkg prefix fishbot_patrol_v2)/share/fishbot_patrol_v2/tools/patrol.sh
bash "$SH"                 # 默认路线 main，跑 1 轮
bash "$SH" main 0 1        # 路线 main，once，1 轮
bash "$SH" main 1 3        # 路线 main，repeat，3 轮
```

### 停止

| 想干什么 | 命令 |
|---|---|
| 取消当前巡检（车停下） | 在 launch 终端 `Ctrl+C`（v0.2.2 起会先取消 Nav2 目标再退出） |
| 暂停 / 恢复 | `ros2 service call /patrol/pause fishbot_patrol_interfaces/srv/PausePatrol "{}"`<br>`ros2 service call /patrol/resume fishbot_patrol_interfaces/srv/ResumePatrol "{}"` |
| 只让当前点位作废、继续跑 | `ros2 topic pub --once /patrol/preempt std_msgs/msg/String "{data: ''}"` |

> **注意**：Humble 的 `ros2 action` 没有 `cancel` 子命令，在 `send_goal` 那个终端按
> `Ctrl+C` 也**不会**取消服务端目标——车会继续把这一轮跑完。

## 4. 存路线（含期望值）

前提：**定位已经起来并且收敛**（否则采到的点位是飘的）。

```bash
ros2 topic echo /amcl_pose --once         # 确认有定位

ros2 service call /patrol_route/record_point \
  fishbot_patrol_interfaces/srv/RecordPoint \
  "{route_name: 'main', point_id: 'p1', task_id: 'inspect', expect: 'present'}"
```

| 字段 | 说明 |
|---|---|
| `route_name` | 路线名，可多路线并存 |
| `point_id` | 点位名，**同路线内不能重复**；留空会自动 `point_001`、`point_002`… |
| `task_id` | 到点要干什么，`inspect`（默认）/ `detect` / `vision` / `yolo` 都会触发视觉 |
| `wait_seconds` | 到点后额外等待，默认 0 |
| `expect` | **新**：`present`（应该有）/ `absent`（应该没有）/ `""`（不判定） |

同一条路线里所有点必须**同一个坐标系**（`frame_id` 不一致会直接报错）。

### `expect` 怎么用才有意义

| 点位实际情况 | 该填什么 | 产生的判定 |
|---|---|---|
| 灭火器就挂在旁边 | `present` | 检出 → `tp`；没检出 → `fn`（漏检） |
| 空会议室、走廊尽头 | `absent` | 检出 → `fp`（误报）；没检出 → `tn` |
| 不确定 / 懒得填 | `""` | 不参与统计，行为与旧版一致 |

不填就完全不判定。**填了之后每跑一轮，报告里自动有召回率和误报率**，不用人工核对。

存完查看：

```bash
ros2 service call /patrol_route/get fishbot_patrol_interfaces/srv/GetRoute "{route_name: 'main'}"
cat ~/.ros/fishbot_patrol_routes.json          # 也可以直接看文件
```

其它操作：

```bash
ros2 service call /patrol_route/set_active fishbot_patrol_interfaces/srv/SetActiveRoute "{route_name: 'main'}"
ros2 service call /patrol_route/clear fishbot_patrol_interfaces/srv/ClearRoute "{route_name: 'main'}"
```

## 5. 跑一轮 + 看结果

```bash
ros2 action send_goal /execute_patrol \
  fishbot_patrol_interfaces/action/ExecutePatrol \
  "{route_name: 'main', mode: 0, repeat_count: 1}" --feedback
```

`mode`：`0`=once、`1`=repeat、`2`=random。

### 实时看板

```bash
ros2 run fishbot_patrol_v2 patrol_viewer
```

表头每帧刷新，含：当前点位、已用时间、检测结果与置信度、本轮成功/失败点数、
电量（低于阈值标红）。退出后两张表以 CSV 落到 `--out-dir`（默认 `~/patrol_viewer`）。

```bash
ros2 run fishbot_patrol_v2 patrol_viewer --ros-args \
  -p out_dir:=$HOME/patrol_reports -p battery_warn_v:=11.8 -p battery_crit_v:=11.5 \
  -p live:=false
```

### 报告

```bash
ls -lt ~/patrol_reports | head            # 每轮三件套：.jsonl / .summary.json / .csv
```

v0.3.3 的 summary 里多了这些字段：

```bash
python3 -c "
import json,glob
p=sorted(glob.glob('$HOME/patrol_reports/*.summary.json'))[-1]
s=json.load(open(p))
for k in ('points_total','points_ok','points_failed','points_skipped',
          'verdicts','graded_points','recall','precision','false_alarm_rate',
          'battery_v','battery_level','duration_sec'):
    print('%-18s %s' % (k, s.get(k)))
"
```

> `recall` / `precision` / `false_alarm_rate` 在没有任何 `expect` 时是 **`null` 而不是 0**
> —— 0 会被误读成"准确率为零"。看到 `null` 就是这条路线还没填期望值。

汇总多轮：

```bash
python3 ~/fishbot_full_ws/src/fishbot_patrol_v2/tools/summarize_runs.py --dir ~/patrol_reports
# 只看最近 3 次：--last 3 ；另存 CSV：--csv ~/summary.csv
```

## 6. 视觉联调要点

### 6.1 确认跑的是对的那个模型

启动日志第一行必须是：

```
Loading YOLO model: .../share/fishbot_vision/fire_extinguisher.pt ...
yolo_detector started, ..., conf=0.15, ...
```

如果出现 `yolo26n.pt`、或者 `bottle` / `person` 这类 COCO 类名，说明模型错了
（launch 覆盖了 yaml，或者装的是老副本）。

### 6.2 相机不通的三步排查

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.100/capture   # 200 正常
arp -n | grep 192.168.1.100                                            # 看 MAC 在不在
curl -s http://192.168.1.100/status | head -c 200                      # 看参数
```

| 现象 | 结论 |
|---|---|
| ping 不通、ARP 里也没有 | 没通电 / 没连这个网 |
| ping 不通、ARP 里有 MAC 但状态 STALE | 掉线，等 10 s 或断电重启 |
| ping 通、80/81 全超时 | **httpd 卡死，必须断电重启**（这颗 ESP32 的固件毛病） |
| 能取图但很慢（>1 s/张） | 热点/信号问题，换位置或接回路由器 |

### 6.3 分辨率必须是 640×480

```bash
curl -s http://192.168.1.100/status | grep -i framesize
```

ESP32 断电或客户端断开后会**自己退回 320×240**，所以每次联调前都值得看一眼。

### 6.4 手动拍照（攒负样本/补数据）

```bash
python3 ~/fishbot_full_ws/src/fishbot_vision/scripts/photo.py --count 20 --interval 0.5
```

打到 `~/shots/`，文件名带时间戳，不会覆盖。

## 7. 走近复核

置信度落在灰区时，车往前挪 0.4 m 再看一眼，最多 2 次。参数在 `patrol_v2.yaml`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `recheck_forward_m` | `0.4` | 每次前进距离，设 `0.0` 就关掉 |
| `recheck_max_rounds` | `2` | 最多走近几次 |
| `recheck_conf_low` | `0.25` | 低于它算"没看到"（会继续走近确认） |
| `recheck_conf_high` | `0.60` | 高于它直接确认，不再走近 |
| `recheck_on_miss` | `true` | 完全没检出也走近确认（压漏检） |

**怎么知道它触发了**：报告里该点位会出现一条 `recheck` 事件，`message` 尾部带
`[recheck +0.4m, top=0.52]`；看板备注列也会显示。

**什么时候别开**：走廊很窄、点位贴着墙（前进 0.4 m 会撞）。先把
`recheck_forward_m` 降到 `0.2`，或对那条路线单独关掉。

## 8. 电量（v0.3.3 起会参与决策）

固件通过 micro-ROS 发 `/battery/voltage`（`std_msgs/Float32`），1 Hz。

```bash
ros2 topic hz /battery/voltage
ros2 topic echo /battery/voltage --once
```

### 8.1 三档与动作

| 档位 | 判定 | 执行器动作 |
|---|---|---|
| `ok` | > `battery_warn_v` | 正常跑 |
| `warn` | ≤ `battery_warn_v` | 只记日志 + 看板标黄，**不中止** |
| `crit` | ≤ `battery_crit_v` | **跑完当前点位**后中止整轮（发布 `battery_abort` 事件） |
| `unknown` | 超过 `battery_stale_sec` 没有新数据 | 当"不知道"，一律不中止（不拿旧电压做决策） |

**为什么是"跑完当前点"而不是立刻停**：车在走廊中间停下会挡住其他人，
也不容易续跑。跑完当前点再停，车在点位上，`resume` 能从下一个点接着来。

### 8.2 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `battery_enabled` | `true` | 关掉就完全不看电量 |
| `battery_topic` | `/battery/voltage` | 电压话题 |
| `battery_warn_v` | `11.8` | 12V 铅酸 11.8 / 3S 锂电 10.8 |
| `battery_crit_v` | `11.5` | 12V 铅酸 11.5 / 3S 锂电 10.2 |
| `battery_hyst_v` | `0.4` | 回差：回到"阈值+0.4"才解除 |
| `battery_stale_sec` | `30.0` | 超时无数据 → `unknown` |
| `battery_window` | `5` | 中值滤波窗口 |

### 8.3 标定

万用表量电池端电压，同时读 `/battery/voltage`，按比例改固件里的
`BAT_DIVIDER_RATIO`。**默认 5.0 只对 5:1 分压电阻有效**，没量过别信绝对值。

> 加速瞬间电压会掉 —— 中值滤波能挡掉单点尖峰，但持续大电流时读数偏低是正常的。
> 所以判定只在**停稳后**做（执行器在点位等待时取值），不在行进中报警。

## 9. 排障表

| 症状 | 根因 | 处理 |
|---|---|---|
| 看板电量显示 `—（N s 未更新）` | `/battery/voltage` 没数据 | 固件没烧 / 话题名不同 / micro-ROS 没连上；先 `ros2 topic list | grep battery` |
| 升级后话题"发出去没人收" | 只重编了 `patrol_v2`，没编 `interfaces` | 两个包一起编；`ros2 pkg xml` 两版本都要对 |
| `'bool' object is not callable` | 旧版把属性当回调传 | 装 ≥0.2.5；`grep -c "cancel_check=lambda" <node.py>` 应为 1 |
| `ignored unmatched external result ...-1` | 有老版本执行器在发 `-1` 格式的 id | `ros2 topic info /patrol/task/request -v` 看发布者 |
| `requesting incompatible QoS ... DURABILITY` | 视觉发结果是 VOLATILE，任务管理器订阅要 TRANSIENT_LOCAL | v0.2.9 起视觉已改 VOLATILE |
| 点位全 `SUCCEEDED` 但没检测结果 | `task_id` 不在白名单 | 用 `inspect`/`detect`/`vision`/`yolo` |
| `recall` / `precision` 一直是 `null` | 路线里没有 `expect` | 按第 4 节给点位加 `present`/`absent` |
| `Stale frame (2.0s old...)` | 相机断流 | 见 6.2；capture 模式下不该出现 |
| `colcon build` 只用 1.4 秒、版本没变 | 时钟回 1970，make 认为源码没更新 | `rm -rf build/x install/x` 再编 |
| `Duplicate package names` | `src/` 里有 `xxx.bak.时间`，或解压错位到工作区根 | 备份挪出去；解包前确认 `pwd` 是 `src/` |
| `ModuleNotFoundError: fishbot_patrol_v2` | 没 `source`，或包没编过 | 重新 source |
| 到点位不停稳就判成功 | 容差 0.30 m / 0.60 rad | 改 `final_position_tolerance_m: 0.10` |
| 相机 IP 变了 | 热点 DHCP | 设静态 IP，或改 `stream_url` |

```bash
unzip -o ~/Downloads/fishbot_patrol_v0.3.3_20261029.zip -d .   # 注意 pwd 必须是 src/
mv fastdds_unicast.xml ~/                                      # 配置别留在 src 里
cd ~/fishbot_full_ws

rm -rf build/fishbot_patrol_v2 install/fishbot_patrol_v2 \
       build/fishbot_patrol_interfaces install/fishbot_patrol_interfaces
colcon build --packages-select fishbot_patrol_interfaces fishbot_patrol_v2 --symlink-install
source install/setup.bash
```

或用随包的升级脚本（会先备份旧包）：

```bash
bash ~/fishbot_patrol_v2/tools/upgrade_patrol.sh ~/fishbot_patrol_v0.3.3_20261029.zip
```

几点注意：

- **备份目录不能留在 `src/` 里**，否则 `colcon` 会把 `xxx.bak.时间` 当成第二个同名包，
  报 `Duplicate package names`。挪到 `~/patrol_backups/`，或放一个空的 `COLCON_IGNORE`。
- **接口包必须一起重编**，只换 `patrol_v2` 会出现"发出去没人收"，且没有任何报错。
- `colcon build` 只用 1~2 秒就"成功"通常不是好事：多半是系统时钟回退导致 make
  认为源码没变。`date` 看一眼，不对劲就 `rm -rf build/x install/x` 重编。
- 编完一定要**重启 launch**，老进程里还是老代码。

## 附：一次完整的联调流程（照着敲）

```bash
# 0) 虚拟机上
source /opt/ros/humble/setup.bash && source ~/fishbot_full_ws/install/setup.bash

# 1) 确认相机
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.100/capture   # 要 200

# 2) 起视觉（机器人上）
ros2 launch fishbot_vision vision.launch.py
#    看到 "YOLO model loaded" + "camera capture polling 5.0Hz (640x480)"

# 3) 起导航（虚拟机上，若还没起）
ros2 launch fishbot_navigation navigation.launch.py

# 4) 起巡检
ros2 launch fishbot_patrol_v2 patrol_v2.launch.py

# 5) 确认定位收敛
ros2 topic echo /amcl_pose --once

# 6) 存 3 个点（前两个应该有灭火器，第三个是空点位）
ros2 service call /patrol_route/record_point fishbot_patrol_interfaces/srv/RecordPoint \
  "{route_name: 'main', point_id: 'p1', task_id: 'inspect', expect: 'present'}"
ros2 service call /patrol_route/record_point fishbot_patrol_interfaces/srv/RecordPoint \
  "{route_name: 'main', point_id: 'p2', task_id: 'inspect', expect: 'present'}"
ros2 service call /patrol_route/record_point fishbot_patrol_interfaces/srv/RecordPoint \
  "{route_name: 'main', point_id: 'p3', task_id: 'inspect', expect: 'absent'}"

# 7) 跑一轮
ros2 action send_goal /execute_patrol fishbot_patrol_interfaces/action/ExecutePatrol \
  "{route_name: 'main', mode: 0, repeat_count: 1}" --feedback

# 8) 看结果（重点看 recall / precision / false_alarm_rate）
python3 ~/fishbot_full_ws/src/fishbot_patrol_v2/tools/summarize_runs.py --dir ~/patrol_reports | tail -20
```
