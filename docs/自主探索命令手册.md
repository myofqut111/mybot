# 自主探索 命令手册（mybot_explore）

> 适用版本：`mybot_explore 0.2.10`（本文件随 0.2.10 更新：扫描门控 + 收工回起点）
> 机器上装的是改名前的包名，**执行命令时把 `mybot_` 换成 `fishbot_`**
> 最后更新：2026-11-13

---

## 1. 一句话

独立功能包，和巡检并列：**不改任何现有包**，只订阅地图和激光、调用 Nav2 的
`navigate_to_pose`，自己决定"下一个该去哪"。

- 巡检 = 按清单跑（点位是录好的）
- 探索 = 自己找活干（点位是自己算出来的）

---

## 2. 前置条件（三件套，缺一不可）

| 条件 | 怎么确认 | 不满足的后果 |
|---|---|---|
| 有地图 | `ros2 topic hz /map` 有输出，或直接给 `map_yaml` | `map_ready: false`，停在 idle |
| 车有定位 | `ros2 run tf2_ros tf2_echo map base_link` | 发不出目标，或全判失败 |
| 激光在流 | `ros2 topic hz /scan` | 能走但擦图不生效，走一步就"到头了" |

> **定位这一条最容易漏**。车没定位就发目标，nav2 一直回失败，探索会以为
> "这个点不可达"，把好好的前沿点拉黑——所以要等 RViz 里车出现在地图上再启动。

---

## 2.5 两种地图模式（先看这个）

| 模式 | 怎么起 | 地图从哪来 |
|---|---|---|
| **静态图**（默认） | `robot.launch.py map_yaml_file:=<pgm> ...` | 事先建好的 pgm |
| **SLAM 模式** | `robot.launch.py localization:=slam ...` | `slam_toolbox` 实时建图，边建边探 |

- SLAM 模式下**不要**传 `map_yaml_file`（导航栈不启 `map_server`），
  探索节点也**不要**传 `map_yaml` —— 留空即订阅 `/map`，谁发的都行。
- 空字符串不能写成 `-p map_yaml:=`（rcl 报 `Couldn't parse parameter override rule`），
  要么不传，要么给一个真实路径。
- SLAM 模式会自动跳过定位门控（没有 AMCL 协方差可判），**不需要**先在 RViz 给 2D Pose Estimate。
- 没有硬件也能试：`python3 src/mybot_explore/tools/sim_base.py` 起假底盘
  （听 `/cmd_vel` 积分位姿、前向 180° 激光，身后永远是未知区），
  配 `navigation.launch.py localization:=slam` 可在虚拟机里跑完整闭环。

## 3. 启动方式（三档，一层比一层主动）

```bash
# ① 看图模式（默认）：只发红球，车一动不动
ros2 run mybot_explore explore_node

# ② 看图 + 指定地图文件（不必等 Nav2，开机就能算）
ros2 run mybot_explore explore_node --ros-args \
    -p map_yaml:=/home/my/maps/map_v2.yaml

# ③ 开车模式，但要按一下才走
ros2 run mybot_explore explore_node --ros-args -p drive:=true
ros2 service call /explore/start std_srvs/srv/Trigger

# ④ 开车模式，起来就自己跑
ros2 run mybot_explore explore_node --ros-args -p drive:=true -p autostart:=true

# 用 launch（带 yaml 参数文件）
ros2 launch mybot_explore explore.launch.py drive:=true autostart:=true

# 停
ros2 service call /explore/stop std_srvs/srv/Trigger
```

> `map_yaml` 可以不给：不给就订阅 `/map`（`map_server` 或 `slam_toolbox` 发的）。
> 给了就直接读 pgm，**不用等 Nav2**，适合离线看图。

## 4. 参数

### 4.1 看图（前沿怎么算）

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `map_topic` | `/map` | 用别的图话题时 |
| `base_frame` | `base_link` | 车机座架不是 base_link 时（常见 `base_footprint`） |
| `period_s` | `1.0` | 想算得更勤（0.5）或更省 CPU（2.0） |
| `min_size` | `4` | 碎点太多 → 调大到 8~12；一个都找不到 → 调到 2 |
| `unknown_radius_m` | `1.0` | "去了能看见多少未知"的统计半径 |
| `max_candidates` | `20` | 一次最多给几个候选 |
| `min_separation_m` | `1.0` | 候选挤在一起 → 调大；想精细选点 → 调小到 0.5 |
| `goal_clearance_m` | `0.35` | 目标老被 nav2 拒"在障碍里" → 调到 0.5（车大就更大） |
| `w_distance` | `0.6` | 想让车优先去近的 → 调大 |
| `w_gain` | `0.4` | 想让车优先去"能看见一大片"的 → 调大 |

### 4.2 擦图（让未知边界往后退）

静态地图不会自己更新，未知边界永远不动，车走到边上就"到头了"。擦图用激光把
光束经过的未知格改成空闲，边界跟着车后退，才能一层层往里探。

| 参数 | 默认 | 说明 |
|---|---|---|
| `carve_enabled` | `true` | 关掉就退化成"只走到已知边界为止" |
| `carve_max_range_m` | `4.0` | 只信这么远以内的光束（远处噪声大） |
| `carve_robot_radius_m` | `0.25` | 车身这一圈直接擦成空闲 |
| `carve_period_s` | `0.5` | 最快多久擦一次 |

### 4.3 开车（怎么走、什么时候放弃）

| 参数 | 默认 | 说明 |
|---|---|---|
| `drive` | `false` | **true 才会真的发导航目标** |
| `autostart` | `false` | true 起来就跑，false 等 `/explore/start` |
| `nav_action` | `navigate_to_pose` | 换导航 action 时改 |
| `visited_radius_m` | `1.2` | 走过一个点，周围这么大算"看过"（不重复去） |
| `min_goal_distance_m` | `0.8` | 太近的点不去，免得原地打转 |
| `max_goal_distance_m` | `15.0` | 太远的点不去（走一半没电更糟） |
| `settle_s` | `1.0` | 到点后等多久再重算前沿（等激光扫一圈） |

### 4.4 超时与收工

| 参数 | 默认 | 说明 |
|---|---|---|
| `nav_timeout_s` | `90.0` | 单个目标最多给这么久，超时算失败 |
| `stuck_window_s` | `15.0` | 这么久没挪窝、也没转够角度，才算卡住 |
| `stuck_move_m` | `0.08` | 位移门槛：15 秒内挪不到 8 cm |
| `stuck_move_rad` | `0.30` | **转角门槛**：原地转 17° 以上也算"在动"，避免把"转圈看环境"误判成卡住 |
| `final_approach_m` | `0.5` | 距目标这么近时不做卡住判定（最后半米本来就是在反复对准） |
| `near_goal_timeout_s` | `15.0` | 但"临近目标豁免"最多续这么久，之后恢复卡住判定 |
| `progress_epsilon_m` | `0.15` | 判定"在进步"的最小距离 |
| `max_consecutive_failures` | `10` | 连续 **abort/超时** 这么多次才收工（`stuck` 不计入） |
| `max_blacklist` | `60` | 拉黑的目标攒到这个数才判定"确实没得探了" |
| `max_duration_s` | `1200.0` | 整场最多 20 分钟 |
| `return_home` | `true` | 探完回起点 |
| `no_frontier_grace_s` | `30.0` | 没有候选时先观察 30 秒，期间未知区还在缩小就继续探 |
| `unknown_drop_cells` | `20` | 未知格子少掉这么多格，就把上面那个 30 秒重新计时 |

> **为什么 `stuck` 不再直接终止**：真机上一片区域连着不可达非常常见（桌子底下、门后、玻璃前），
> 0.2.0 曾用"连续卡住 5 次就收工"的熔断，结果车还有 20 个前沿就自己停了。现在卡住只计数、只拉黑，
> 真正决定收工的是"黑名单攒满"或"确实没有前沿了"。

### 4.5 收工自动存图（0.2.6）

跑完不用手动 `map_saver`，收工那一刻自动存：

| 参数 | 默认 | 说明 |
|---|---|---|
| `auto_save` | `true` | 收工自动存图 |
| `save_map_dir` | `~/maps` | 存到哪 |
| `save_map_prefix` | `explore` | 文件名前缀，后面接 `_年月日_时分` |
| `save_map_service` | `/slam_toolbox/save_map` | slam 模式走这个服务 |
| `map_despike` | `true` | 存完再做一次 3×3 中值去毛刺 |

产出三个文件：

```
~/maps/explore_20261116_1905.pgm          # 原始
~/maps/explore_20261116_1905.yaml
~/maps/explore_20261116_1905_clean.pgm    # 去毛刺版（推荐用这个）
```

日志里会打一行质量指标：

```
去毛刺：/home/my/maps/explore_20261116_1905_clean.pgm（孤立障碍 7.8% → 4.3%）
```

**"孤立障碍率"是什么**：障碍格里，8 邻域内只有 ≤1 个障碍邻居的格子占比。
激光噪点的典型形态就是"孤零零一个黑点"，所以这个数越小越干净。
实测 `map_newst` 7.76% → 4.26%，`map_v2` 6.30% → 3.03%，墙线一根没少。

> 中值滤波只清**孤立点**，清不掉"成片的放射状毛刺"（玻璃、镜子、人挡着的那一片）。
> 那种要靠调 SLAM 参数（`max_laser_range`、`minimum_travel_*`）或多角度重访。

## 4.7 打滑与低矮障碍（0.2.8）

车会遇到"雷达看得见、但过不去"的地方（桌子底下、凳子腿之间、门槛）。
这时 odom 还在累加、扫描却一动不动，SLAM 会用错误的位姿继续拼图，地图就撕了。

节点现在会自己发现这件事，并且**只标有物证的部分**：

| 判据 | 含义 |
|---|---|
| A：`map→odom` 在长 | SLAM 说车没动、odom 说在走 → odom 在说假话 |
| B：近场扫描没变、odom 在涨 | 只统计近场命中束，变化率低于 15% 算"扫描认为车没动" |
| 排除 | 原地转（`|ω|>0.3`）、命中束太少（<20）、命令速度≈0 |

A 且 B 持续 `slip_confirm_s`（1.5 s）后：

1. 取消当前导航目标
2. 调 `/slam_toolbox/pause_new_measurements`（切换型服务，暂停建图）
3. 在**车头前沿**画一条 **0.5 m 短墙**（垂直朝向；车宽 0.3 + 两侧各 0.1）
4. 记一个挡住点写进 `~/.ros/mybot_blocked.json`
5. 该点进黑名单 1.0 m（**只影响选点，不写进地图**）
6. 车真动起来 → 再调一次同一个服务恢复建图

**其余保持未知（灰）**：车没走到的地方就是没走到，不编造黑区。

相关参数（`config/explore.yaml`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `slip_enabled` | `true` | 总开关 |
| `slip_odom_min_m` | `0.05` | 一拍里 odom 走这么多才算在动（≈0.1 m/s 下限） |
| `slip_map_odom_min_m` | `0.08` | `map→odom` 漂这么多 = odom 在说假话 |
| `slip_scan_change_ratio` | `0.15` | 变化束占比低于它 = 扫描认为车没动 |
| `slip_scan_near_m` | `3.0` | 先只看这么近；命中太少会自动放宽 |
| `slip_min_hits` | `20` | 命中束少于它就不判（空旷区没有可比性） |
| `slip_confirm_s` | `1.5` | 持续这么久才确认 |
| `blocked_wall_len_m` | `0.50` | 短墙长度（车宽 + 余量） |
| `keepout_radius_m` | `1.00` | 禁试区半径（不写地图） |
| `blocked_file` | `~/.ros/mybot_blocked.json` | 跨轮次记录，可手工删改 |

排障：

- 日志出现 `疑似低矮障碍：…扫描只变了 0%（近场 6.0 m 内 360 束），map→odom 漂了 0.39 m` → 正常
- 出现 `暂停服务还没就绪` → slam_toolbox 还没起来或服务名不对（应为 `/slam_toolbox/pause_new_measurements`）
- 存图时短墙会盖进 `*_clean.pgm`；原始 `.pgm` 不含推断内容

## 4.8 扫描门控与收工回起点（0.2.9）

### 为什么不再"暂停建图"

0.2.8 里打滑确认后调的是 `/slam_toolbox/pause_new_measurements`。这个服务**只有全局语义**：
一调，整张图停止接收任何扫描。车打完滑点再往前走，地图也不会更新；`give_up` 分支还写着
"仍保持暂停"，等于**永久冻结建图**。

0.2.9 改成**扫描门控**：

```
/scan ──▶ scan_gate ──▶ /scan_filtered ──▶ slam_toolbox
              ▲
              └── /explore/scan_gate (std_msgs/Bool)   ← 探索节点发布
```

- 打滑确认 → 发布 `true`，`scan_gate` **丢掉这几帧**，地图照常在跑（其它时段不受影响）
- 车真动起来 → 发布 `false`，立刻恢复
- 放弃该点 → **也发布 `false`**（这一点很关键：以前就是这里把图冻死的）
- 兜底：`max_closed_s`（默认 5 s）到点强制放行，什么都不发也不会冻图

`/explore/status` 里的字段从 `slam_paused` 改成 `scan_gate: "closed" | "open"`。

### 收工一律先回起点

以前只有"没有前沿了"才回家；超时、连续失败、黑名单满都是**就地收工**，于是地图没有回环，
末尾那一段永远是散的。现在四种自然收工都先回家：

| 收工原因 | 以前 | 现在 |
|---|---|---|
| `map_complete` | 回家 | 回家 → 等 3 s → 存图 |
| `timeout` | 就地停 | 回家 → 等 3 s → 存图 |
| `too_many_failures` | 就地停 | 回家 → 等 3 s → 存图 |
| `too_many_blacklisted` | 就地停 | 回家 → 等 3 s → 存图 |

`stop_reason` 记**为什么停**，`returned_home` 记**有没有回到起点**，`loop_closure` 记
`pending / settled / failed / skipped`。存图发生在回家并停稳之后 —— 那时候才吃得上回环。

### 新增参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `scan_gate_enabled` | `true` | 关掉就退回"打滑只拉黑、不丢帧" |
| `scan_gate_topic` | `/explore/scan_gate` | 门控控制话题 |
| `home_settle_s` | `3.0` | 到家后等多少秒再存图（等回环收敛） |
| `home_timeout_s` | `120.0` | 回家单独的超时，比普通目标宽松 |

`scan_gate` 节点本身还有 `max_closed_s`（5.0）与 `silence_warn_s`（2.0），由 launch 参数
`scan_gate_max_s` 透传。

### 三个要看的日志

```
扫描门控：关闭（打滑确认）—— 这几帧不进图，建图继续
扫描门控：打开（车已恢复移动）
打滑后 10 秒仍没动起来，放弃这个点（已恢复建图）
```

只要看到第二/第三条，就说明**图不会再冻住了**。

## 4.8 推台阶 / 顶矮墙（0.2.12）

车顶住台阶时不会立刻停：轮子打滑、`/odom` 照样在涨，可**车在世界里其实没动**。

| 现象 | 说明 |
|---|---|
| odom 在涨 | EKF 只看轮子，轮子转了它就认为车走了 |
| 扫描没变 | 车真的没动，一圈激光打到的还是那堵矮墙 |
| `map→odom` **不漂** | slam 没有依据去修正（车确实没动），所以"打滑判据 A"恒为 0 |

> 所以顶住台阶时**打滑判据永远不成立**（它要求 A 且 B）。这就是"车一直往前顶"的原因。

### 判据（只靠 B）

跨 `block_window_s`（3 s）比较两帧扫描：

- 1 m 内命中 ≥ `block_min_hits`（8 束）
- 变化束占比 < `block_scan_change_ratio`（10%）
- odom 涨了 ≥ `block_odom_min_m`（0.30 m）
- 且确实在往前开：`|linear| ≥ block_min_speed`、`|angular| ≤ block_max_omega`
- 连续满足 `block_confirm_s`（1 s）

### 动作

取消当前目标 → 在车头前沿标一段短墙（只标物证，不铺一片）→ 记进 `~/.ros/mybot_blocked.json` → 拉黑这一片（半径 `keepout_radius_m`）→ 换下一个前沿。

**不关扫描门控**：这种情况扫描是可信的（墙真的在那儿），关掉反而丢证据。

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `blocked_enabled` | true | 总开关 |
| `block_window_s` | 3.0 | 跨多久比两帧 |
| `block_odom_min_m` | 0.30 | odom 至少涨这么多才算"顶住" |
| `block_scan_change_ratio` | 0.10 | 变化束占比阈值 |
| `block_scan_near_m` | 1.0 | 只看这么近的束 |
| `block_min_hits` | 8 | 近场至少几束 |
| `block_min_speed` / `block_max_omega` | 0.05 / 0.20 | 只在"往前开"时判 |
| `block_confirm_s` / `block_cooldown_s` | 1.0 / 5.0 | 确认窗口 / 冷却 |
| `slip_debug` | false | 打开后每 2 s 打一行"滑移诊断" |

### 日志长这样

```
[WARN] 疑似被顶住（台阶/矮障）：车在 (1.20, 0.00)，odom 3.00 秒里涨了 0.45 m，
       但 1.0 m 内 69 束扫描只变了 0%
[INFO] 已把这一片列为禁试区（半径 1.0 m），换下一个点
```

### 排障

| 症状 | 原因 |
|---|---|
| 顶住却不报 | `slip_debug=true` 看 `linear` 是不是 0（没在发 /cmd_vel 就不判） |
| 老误报 | `block_scan_near_m` 调小到 0.8，或把 `block_odom_min_m` 提到 0.4 |
| 报得太勤 | 加大 `block_cooldown_s` |

## 4.9 里程计锚点 odom_shim（0.2.11）

### 治的是什么

扫描门控只管"坏帧不进图"，**管不了位姿本身**。位姿链是三段复合的：

```
map --(slam)--> odom --(EKF)--> base_link
```

打滑时车没动，但编码器还在累加，EKF 那段 `odom→base_link` 一直涨；slam 那段
`map→odom` 要反过来抵消它。一旦建图被暂停或跟不上，**复合位姿就跟着漂**，
恢复后同一面墙被当成新地方拼上去 —— 这就是"两张图拼在一起"。

### 做法

把 `odom→base_link` 的发布权从 EKF 手里接管过来：

| 时刻 | 行为 |
|---|---|
| 平时 | `发布 = 原始 + offset`（offset 为 0） |
| 打滑确认（`/explore/scan_gate` = true） | **冻结**：一直发同一个位姿 |
| 恢复（= false） | **重锚**：`offset = 冻结位姿 − 当前原始位姿`，那一段假位移永久丢弃 |

EKF 内部怎么涨都无所谓，对外位姿始终是"老实"的。

### 怎么开

只在**探索**时开，巡检保持默认（否则没接管成功就没有 `odom→base_link`）：

```bash
ros2 launch fishbot_console robot.launch.py \
  localization:=slam rviz:=false \
  ekf_publish_tf:=false odom_shim_enabled:=true
```

- `ekf_publish_tf:=false` —— EKF 不再发 TF
- `odom_shim_enabled:=true` —— 由 `odom_shim` 发 `odom→base_link`

### 三个要看的日志

```
odom_shim 已启动：odom → base_link（源 /odometry/filtered，冻结信号 /explore/scan_gate）
里程计已冻结在 (1.23, -0.45, 0.31 rad)，打滑期间的位移不再计入位姿
里程计已重锚：丢掉假位移 0.39 m（累计 0.39 m，第 1 次），继续从当前位姿走
```

第三条里的米数，就是**这次打滑从位姿链里被删掉的假位移**。

### 状态与排障

```bash
ros2 topic echo /odom_shim/state --once
# {"frozen": false, "offset": [-0.39, 0.0, 0.0], "freezes": 1, "resumes": 1,
#  "discarded_m": 0.39, "frozen_pose": null, "age_s": 0.02}
```

| 症状 | 原因 | 处理 |
|---|---|---|
| RViz 里没有 `odom→base_link`，一切飘 | 开了 `odom_shim_enabled` 但没关 `ekf_publish_tf`（两个发布者打架），或 shim 没起来 | 两个参数必须成对给 |
| `age_s` 一直涨、日志刷"里程计断流" | EKF 没出 `/odometry/filtered` | 查 EKF 输入 `/odom`、`/imu` |
| `freezes` 很大但车没打滑 | 打滑判据太敏感 | 调 `slip_scan_change_ratio` / `slip_map_odom_min_m`，见 4.7 |

### 代价

重锚会把打滑期间**真实发生的那几厘米位移一起丢掉**（判断为"车没动"）。这是有意的取舍：
宁可少算几厘米，也不要让假位移把地图拼歪。

## 5. 话题与服务

| 名称 | 类型 | 方向 | 内容 |
|---|---|---|---|
| `/map` | `nav_msgs/OccupancyGrid` | 订阅 | 地图（TRANSIENT_LOCAL） |
| `/scan` | `sensor_msgs/LaserScan` | 订阅 | 激光（BEST_EFFORT 也能收） |
| `/explore/frontiers` | `visualization_msgs/MarkerArray` | 发布 | 候选前沿点（分数越高越红） |
| `/explore/candidates` | `geometry_msgs/PoseArray` | 发布 | 同上，给工具用 |
| `/explore/blacklist` | `visualization_msgs/MarkerArray` | 发布 | 失败过的点（灰块） |
| `/explore/status` | `std_msgs/String` | 发布 | 状态 JSON（见下） |
| `/explore/start` | `std_srvs/Trigger` | 服务 | 开始探索 |
| `/explore/stop` | `std_srvs/Trigger` | 服务 | 中止并回起点 |

## 6. `/explore/status` 字段

```bash
ros2 topic echo /explore/status
```

| 字段 | 含义 |
|---|---|
| `state` | `idle` / `select` / `navigate` / `settle` / `return_home` / `done` |
| `done_reason` | 收工原因：`no_frontier` / `returned_home` / `max_duration` / `failed` |
| `goals` / `succeeded` / `failed` | 一共发了几个目标、成功几个、失败几个 |
| `blacklist` | 已拉黑的点数 |
| `consecutive_failures` | 连续失败次数（到 3 就收工） |
| `distance_m` | 走了多远 |
| `map_ready` | **图到了没有** |
| `scan_ready` | **激光到了没有** |
| `carved_free` / `carved_occupied` | 擦图累计计数（一直 0 = 激光没进来） |

一眼判读：

| 现象 | 结论 |
|---|---|
| `map_ready: false` | 图没来 → 查 `/map`、查 `map_server` 的 `yaml_filename` |
| `scan_ready: false` | 激光没来 → 查 `/scan`、查 QoS |
| `carved_free` 一直是 0 | 激光来了但没进 `_carve()` → 看 `carve_enabled` |
| `blacklist` 一直涨 | 目标点选在到不了的地方 → 调大 `goal_clearance_m` |

## 7. 验证三步

### 第 1 步：离线看图（不用 ROS，30 秒）

```bash
cd ~/fishbot_full_ws
python3 src/fishbot_explore/tools/explore_offline.py \
    ~/maps/map_v2.yaml --pose 8.19 3.17 --min-size 8 --out /tmp/f1.png
```

拷出来看图：灰=未知、白=空闲、黑=墙、红圈=候选、绿点=车、浅蓝=已走过。

**通过标准**：红圈压在"白/灰交界"上，10~30 个，不是满屏乱点。

### 第 2 步：mock（5 分钟，不用真车）

```bash
bash tools/run_mock_explore.sh 120     # 或 VM 上的 /tmp/run_mock_explore.sh
```

**通过标准**：

```
前沿 3 个，最佳 (4.98,4.62)      ← 门口
前沿 1 个，最佳 (6.43,7.33)      ← 走进未知区了
前沿 2 个，最佳 (7.98,8.43)
没有前沿：要么地图还没建，要么已经探完
去 (home) (2.00,2.00)
```

并且"未知面积"从 500 多一路掉到个位数。

### 第 3 步：真机（先看图，再开车）

**3.1 只算不动**（最重要，别跳过）

```bash
ros2 run fishbot_explore explore_node
```

RViz 加两个 Display：`MarkerArray → /explore/frontiers`、`PoseArray → /explore/candidates`。

通过标准：红球出现在你没去过的地方；车挪一下红球跟着重算；终端 1 Hz 刷
`前沿 N 个，最佳 (x,y)`。

**3.2 让它走一个**（手放急停上）

```bash
ros2 run fishbot_explore explore_node --ros-args -p drive:=true -p autostart:=true
```

看三件事：车朝红球走 → 到点停 1 秒 → 红球往后缩（擦图生效）。

## 9. 故障对照表

| 现象 | 根因 | 处理 |
|---|---|---|
| 一直 `前沿 0 个` + `map_ready: true` | 这张图没有灰区（已被探完），或读错了图 | 换有未知区的地图；`ros2 param get /map_server yaml_filename` 核对 |
| `map_ready: false` | 没图 | 起 Nav2 或给 `map_yaml` |
| `carved_free` 一直 0 | `/scan` 没进来（QoS 最常见） | `ros2 topic hz /scan`；订阅端已用 `qos_profile_sensor_data`，还收不到就是发布端没发 |
| 目标全被拒 `在障碍里` | 前沿贴边，落在膨胀区 | 调大 `goal_clearance_m`（0.35 → 0.5） |
| 车来回转圈不去新地方 | 拉黑没生效 / 覆盖层没画 | 看 `blacklist` 和 `visited` 是否在涨 |
| 走了几步就"没有前沿" | 擦图关着 | `carve_enabled: true` |
| 一直 `select` 不发目标 | 目标都太近（`min_goal_distance_m`）或太远（`max_goal_distance_m`） | 调这两个阈值 |
| 起来 10 秒还没动 | 三件套没齐 | 看 `/explore/status` 的 `map_ready` / `scan_ready` |

## 10. 收工条件与安全

自动停的四种情况：

| 什么时候 | `done_reason` |
|---|---|
| 没有前沿、且 30 秒内未知区不再缩小 | `map_complete` |
| 黑名单攒满 60 个 | `too_many_blacklisted` |
| 连续 abort/超时 10 次 | `too_many_failures` |
| 满 20 分钟 | `timeout` |
| 探完回起点成功 | `returned_home` |
| 节点内部异常（已被兜住，不会静默退出） | `internal_error` |

收工时日志会打一行汇总（0.2.1 起）：

```
探索收工：原因 map_complete；目标 12 个（成功 9 / 失败 1 / 超时 0 / 卡住 2），黑名单 5 个，走过 43.2 m
```

随后自动存图（见 §4.5）。

**安全须知**：

1. 第一次上真机**只跑看图模式**（不加 `drive:=true`）
2. 开车必须有人手放急停
3. 探索和巡检**不要同时跑**（两个都发 `navigate_to_pose`，会互相抢目标）
4. 看门狗（`fishbot_safety`）可以同时开，它只管"车在动但没人指挥"的情况

## 11. 和巡检的关系

| | 巡检 `mybot_patrol_v2` | 探索 `mybot_explore` |
|---|---|---|
| 点位从哪来 | 录点（人走到位置记下来） | 算法算（前沿检测） |
| 要不要地图 | 要（导航用） | 要（找未知区用） |
| 结束条件 | 点位跑完 | 没有未知区了 |
| 输出 | 报告（每点检测结果） | 一张被探完的地图 |

两者**并列**，不互相调用。想让"巡检到某点后顺便探一圈"，再做成服务调用，现在不做。
